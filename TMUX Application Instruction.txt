If a session has died between launches, show it as dead on relaunch.

### Session states

A copilot session can have three states: Idle, Running, Awaiting User Input
- **Idle:** When no task is currently underway
- **Running:** When agent is currently working, following an instruction
- **Awaiting User Input:** When an agent requires user to approve an operation or otherwise give input before work can proceed

### State detection

Wrap each Copilot CLI process in a pseudo-terminal (PTY) proxy rather than screen-scraping tmux panes. The proxy sits between the app and the CLI process, reading all output in real-time and feeding it through a state machine.

State heuristics (evaluated in priority order):
- **Awaiting User Input:** Detect known approval prompt patterns (e.g. `Allow`, `Deny`, `(y/n)`, spinner stopped + cursor on an input line)
- **Running:** Output is actively streaming, or a thinking spinner/animation is present
- **Idle:** The input prompt is visible (e.g. `> `) and no output has arrived for 5 seconds

PTY interception is preferred over `tmux capture-pane` because it intercepts every byte in real-time rather than polling, giving reliable state transitions and a clean hook for logging and session persistence.

The exact prompt strings and spinner formats should be confirmed empirically against the installed Copilot CLI version, and kept as configurable patterns rather than hardcoded strings.
